Unity에서 문제(에러/이상 동작/시각 미표시 등)가 발생하면 클로드가 다음 워크플로우를 **사용자 지시 없이 자동**으로 수행한다.

## 워크플로우 (5단계)

### 1. 진단용 디버그 로그 추가
- 의심되는 코드 위치에 `Debug.Log` 추가
- 변수 값, 조건 분기, 진입/종료 시점, 부모 체인, GameObject 상태 등
- 로그 prefix는 컴포넌트 이름으로 통일 (예: `[BuildingView]`, `[TopTowerIngame]`)

### 2. 사용자에게 Play 요청
- "Unity 컴파일 후 Play 해주세요" 정도 짧게
- 캡처 보내달라고 하지 말 것

### 3. Editor.log 자동 읽기
- 경로: `C:\Users\DG-2410-PC-053\AppData\Local\Unity\Editor\Editor.log`
- PowerShell `Get-Content -Tail N` 또는 Bash `tail` 사용
- 추가한 로그 prefix로 필터링

### 4. 분석 → 솔루션 보고
- Editor.log에서 추출한 정보로 원인 추적
- 사용자에게 짧고 명확하게 보고 (원인 + 해결 방안)
- 코드 수정 또는 에디터 설정 변경 안내

### 5. 해결 후 디버그 로그 정리 (필수)
- **해결 확인되면 추가했던 임시 디버그 로그 모두 제거**
- 영구적으로 필요한 로그(에러 케이스, 예상치 못한 상태 등)만 남김
- 임시/진단용 `Debug.Log`는 코드 클린업의 일부

**Why:** 빠른 디버깅을 위해 자동 워크플로우 정착. 사용자가 매번 "콘솔 봐줘", "로그 추가해", "이제 로그 빼" 같은 반복 지시를 안 해도 됨.

**How to apply:**
- 문제 발생 신호("에러", "안 보임", "이상해", "Play 했더니", "안 뜸") 받으면 즉시 진단 모드 진입
- Editor.log 우선 자동 확인, 부족하면 디버그 로그 추가 → 재테스트 → 자동 확인
- **솔루션 확정 후 클린업 단계를 잊지 말 것** — 진단용 로그는 임시. 영구 코드에 남기지 않는다.
- 만약 임시 로그가 영구 가치 있다면(상시 모니터링 등) 사용자에게 짧게 확인 후 남김
